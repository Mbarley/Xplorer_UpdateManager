# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

This is a Klipper firmware configuration repository for the **Formbot Xplorer** 3D printer, maintained by Formbot and distributed via the **Mainsail Update Manager**. Users never clone this manually — Mainsail pulls updates directly from GitHub into `~/printer_data/config/0_Xplorer/` on the printer's Raspberry Pi. There are no build steps, no tests, and no package managers.

## Printer variants

The repo supports two hardware generations and four kinematic modes:

| Variant | Gantries | Extruders | Entry CFG |
|---------|----------|-----------|-----------|
| V1.0 SINGLE | 1 | 1 | `Xplorer_SINGLE.cfg` |
| V1.0 IDEX | 1 | 2 | `Xplorer_IDEX.cfg` |
| V1.1 SINGLE | 1 | 1 | `Xplorer_V1.1_SINGLE.cfg` |
| V1.1 IDEX | 1 | 2 | `Xplorer_V1.1_IDEX.cfg` |
| V1.1 2xGANTRY | 2 | 2 | `Xplorer_V1.1_2xGANTRY.cfg` |
| V1.1 IQEX | 2 | 4 | `Xplorer_V1.1_IQEX.cfg` |

The user's `printer.cfg` on the printer includes exactly one of these entry CFGs. Each entry CFG is a flat list of `[include ...]` directives that pull in all required sub-configs.

## Config architecture

### `01_Default_CFG/` — pushed via Update Manager

All `.cfg` files here are **automatically updated** on users' printers when they click "Update" in Mainsail. Files are split by concern:

- `Xp_Xplorer_Vars.cfg` — central variables (speeds, positions, offsets, timeouts). This is the first place to look when tuning behavior.
- `Xp_Basic_Settings.cfg` — printer limits, custom modules (`[xplorer]`, `[trsync_patch]`), `[save_variables]`.
- `Xp_Tool{0,1}.cfg` / `Xp_V1.1_Tool{2,3}.cfg` — per-tool hardware (extruder, heater, fan, endstop).
- `Xp_{X,Y,Z}_Axis_*.cfg` — axis kinematics, stepper configs, endstops for each variant.
- `Xp_Macros_Base.cfg` — shared macros (Z_TILT_ADJUST, BED_MESH_CALIBRATE, homing, parking).
- `Xp_Macros_{IDEX,SINGLE}.cfg` / `Xp_V1.1_Macros_{IQEX,T2,T3}.cfg` — variant-specific macros (tool changes, copy/mirror modes).
- `Xp_SmartSensor_T{0,1}.cfg` / `Xp_V1.1_SmartSensor_T{2,3}.cfg` — filament runout/load/tangle sensor macros.
- `Xp_Calibrate_offsets_*.cfg` / `Xp_V1.1_Calibrate_offsets_*.cfg` — tool offset calibration procedures.
- `Xp_PLR_{1,2,4}xExtr.cfg` — Power Loss Recovery for each extruder count.
- `Xp_Shell_Commands_*.cfg` — `[gcode_shell_command]` wrappers that invoke the scripts in `.8_Scripts/`.
- `Xp_Mainsail.cfg` / `Xp_Moonraker.cfg` — Mainsail/Moonraker integration macros.

### `02_Printer_cfg/` — reference / bootstrap configs

These are the `printer.cfg` templates users install manually once. They are **not updated** by the Update Manager. They include board serial paths, PID values, bed probe offset, and the single `[include ./0_Xplorer/01_Default_CFG/Xplorer_V1.1_IQEX.cfg]` line pointing into the update-managed configs.

### `.7_XP_modules/` — custom Klipper Python plugins

These are deployed to `~/klipper/klippy/extras/` on the printer:

- `trsync_patch.py` — patches `mcu.TRSYNC_TIMEOUT` from 0.025 → 0.050 to prevent multi-MCU sync errors on IQEX/2xGantry builds.
- `xptools_calibrate.py` / `tools_calibrate.py` — multi-axis nozzle probe calibration for tool offset alignment (`[xptools_calibrate]` section).

### `.8_Scripts/` — shell scripts (run via gcode_shell_command)

- `resonances_X/Y_*.sh` — input shaper measurement scripts per axis and variant.
- `xpplr.sh` / `xpclear_plr.sh` — Power Loss Recovery helpers.
- `xpprint_layer.sh` — called at layer change for PLR bookkeeping.
- `setup_timezone.sh` / `setup_wifi.sh` — printer OS setup utilities.

### `.9_MCU_Flash/` — MCU firmware flashing

Scripts and Klipper `make menuconfig` snapshots for flashing the BTT Manta M8P (v1.1 / v2.0), BTT Pico (expansion), and BTT EBB36 (tool boards T0–T3). See `06_Manual/Flashing_MCUs_manually_KIAUH.pdf` for procedure.

## Key conventions

- **V1.0 files** use no version prefix (e.g. `Xp_Macros_IDEX.cfg`). **V1.1 files** are prefixed `Xp_V1.1_` (e.g. `Xp_V1.1_Macros_IQEX.cfg`).
- All user-tunable runtime values live in `Xp_Xplorer_Vars.cfg` under `[gcode_macro _XPLORER_VARIABLES]`. Sensor behavior is in the per-tool `_SENSOR_t*_VARIABLES` macros inside each printer's local `printer.cfg`.
- Macros that override built-in Klipper commands use `rename_existing: BASE_*` so the original is still callable.
- The `SAVE_CONFIG` block at the bottom of each user's `printer.cfg` (auto-generated by Klipper) is the source of truth for PID, probe z_offset, and bed mesh — never edit that block manually.
